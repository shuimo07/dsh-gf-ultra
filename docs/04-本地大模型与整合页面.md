# 04 - 本地大模型与整合页面

## llama.cpp + Qwen3-4B

```powershell
# llama-server（E:\llama-cpp 已有 CUDA 构建）
E:\llama-cpp\llama-server.exe -m E:\llama-cpp\models\Qwen3-4B-Q4_K_M.gguf `
  -np 1 -c 8192 -fa on --temp 1.0 --host 0.0.0.0 --port 8090
```

- 模型：`Qwen3-4B-Q4_K_M.gguf`（2.5GB，8GB 显存推荐档），hf-mirror：`Qwen/Qwen3-4B-GGUF`
- **必须 `/no_think`**：Qwen3 默认思考模式会把回复全放进 `reasoning_content`，正文为空。在 system prompt 末尾加 `/no_think`。

验证（OpenAI 兼容）：

```
POST /v1/chat/completions
{"messages":[{"role":"system","content":"你叫小雅…\n/no_think"},{"role":"user","content":"你好"}]}
```

## 整合页面（web/）

`web/girlfriend.html` + `web/client.js`，放到 `LiveTalking/web/` 下由 LiveTalking（:8010）伺服（同源调用 `/offer` `/human`）。

流程：

1. 点「连接数字人」→ WebRTC 建立会话，显示数字人视频
2. 语音球：`getUserMedia` → 16kHz PCM16 → 桥接 `POST /api/stt`
3. 文本 → llama `POST /v1/chat/completions`（带 `/no_think` 人设）
4. 回复文本 → `POST /human {sessionid, text, type:'echo'}` → LiveTalking 内部 edge_tts 合成 + wav2lip 渲染，WebRTC 输出音视频

跨域：

- 桥接 `cors_origins` 需要加 `http://127.0.0.1:8010`
- llama-server 默认 `Access-Control-Allow-Origin: *`
- LiveTalking aiohttp_cors 默认 `*`

## 一键启动

`scripts/start-girlfriend.cmd`：检查各端口，未启动则拉起 llama-server / LiveTalking / 桥接，然后打开页面。

## 显存规划（RTX 4060 8GB）

| 组件 | 占用 |
|---|---|
| Qwen3-4B Q4 | ~3GB |
| wav2lip256 | ~1.3GB |
| FunASR (STT) | ~1GB |
| **合计** | **~5.5GB ✓** |

> 整合页说话走 LiveTalking 的 edge_tts（云端免费），不占用显存；DSH 插件里的 Qwen3-TTS 克隆（~3.7GB）与 llama 同时加载会超 8GB，需错开或降级其一。
